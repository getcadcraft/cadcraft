{{cmd:DIAGRAM}} (`TEXTDIAGRAM`、`T2D`) と入力します。ボックスが開くので、テキストを貼り付け、{{ui:作図}} を選び、図の左上の角をクリックして文字の高さを入力します。CadCraft はテキストを読み取り、ブロックを階層ごとに並べて直角のコネクタで結び、`Diagram` という名前のレイヤーに描きます。作成された新しいオブジェクトは選択された状態になるので、すぐに移動できます。これらは通常のオブジェクトです。ブロックの文字は {{cmd:TEXTEDIT}} で変更し、コネクタはグリップで伸ばし、ブロックは削除し、独自の線を追加できます。{{cmd:UNDO}} を1回実行すると、図全体が取り消されます。

ボックスを使わずにコマンドラインで入力する場合は、文の区切りに `;` を使うと、テキストを1行で書けます: `flowchart LR; A[Pump] --> B[Tank]`。

## 読み取れる内容

| テキスト | 読み取られる内容 |
|---|---|
| **Mermaid** で `TD`、`TB`、`BT`、`LR`、`RL` を指定した `flowchart` または `graph` | `A`、`A[text]`、`A(text)`、`A([text])`、`A{text}` (判断。ひし形で描かれます)、引用符付きの文字、`-->`、`---`、`-.->`、`==>`、`--x`、`<-->`、`-->\|text\|` または `-- text -->` のラベル、連鎖 `A --> B --> C`、グループ `A & B --> C`、改行の `<br/>`、`%%` のコメント |
| **PlantUML** の `@startuml` と `@enduml` の間 (コンポーネント図と配置図) | `[Component]`、`component`、`node`、`database`、`cloud`、`actor`、`rectangle` など、`as` で名前を付けたもの、`A --> B : label`、`->`、`..>`、`--`、`left to right direction` |
| **D2** | `a -> b: label`、`a <- b`、`a <-> b`、`a -- b`、連鎖、`a: Label`、`direction: right`、引用符付きの名前、`#` のコメント |
| **from-to リスト** (テキストまたは CSV として貼り付けた表) | `from`、`to` の列と、任意で `label`、`type` の列 (`dashed` を指定すると破線のコネクタになります)。区切りはカンマ、セミコロン、タブのいずれかで、列の順序は問いません。見出し行がない場合は、最初の3列が from、to、label になります。 |

| **draw.io XML** (`.drawio` ファイルのテキスト、`<mxfile>` または `<mxGraphModel>`) | ボックス、角丸ボックス、楕円、ひし形の判断、プレーンテキスト、コンテナとスイムレーンのボックス (タイトル付きの破線で描かれます)、経由点付きのコネクタ、矢印の端 (`endArrow`、`startArrow`)、`dashed=1`。HTML のラベルはプレーンテキストになり、`<UserObject label>` と `<object label>` も使えます。 |

それ以外の行 (スタイル、注記、ループ枠など) は読み飛ばされ、コマンドラインに飛ばした行数が表示されます。1つの図には、最大で 400 個のブロックと 1200 本のコネクタを含められます。

## draw.io XML は位置を保持します

他の形式は何がどこにつながるかだけを示すので、CadCraft が配置を決めます。draw.io XML にはすでに各要素の位置が書かれているため、CadCraft はその位置を保持します。各ブロックはファイルの位置に置かれ、指定した文字の高さに合わせて縮尺されます (12 ピクセルのフォントが指定した文字の高さになります。120×60 ピクセルのボックスは、高さ 6 のとき 60×30 の図面単位になります)。図の左上は、クリックした角に配置されます。コネクタは、一方のブロックの端から次のブロックの端まで、経由点を通って走ります。`orthogonalEdgeStyle` があり経由点がないコネクタには、直角の屈曲が1つ付きます。

draw.io の既定の保存形式は圧縮されています。ボックスとコマンドラインは自動的にそれを開きます。圧縮ストリームのないウィンドウのアシスタントツールでは、その旨が表示されます。その場合は、`File › Export as › XML` で *Compressed* のチェックを外すと、通常の XML が得られます。画像、端が浮いたコネクタ、2ページ目以降は読み飛ばされ、件数が数えられます。

## お使いのコンピューターのモデルで作成する

ローカルモデル (Ollama、LM Studio、llama.cpp、Jan) は、PDF や SVG の内容から XML または Mermaid のテキストを作成できます。結果は同じボックスに貼り付けるか、モデルがアシスタントとして接続されている場合は図面に直接取り込まれます: `diagram_from_text` は `format` に `drawio` を指定します。小規模なモデルは、Mermaid や from-to リストよりも XML で間違いが多くなります。そのため、まずは Mermaid で試す方が手間がかかりません。読み取れないものは推測されず、読み飛ばされて件数が数えられます。モデルの設定例は AIの接続を参照してください。

## 配置の方法

ブロックはコネクタに従って階層に並べられます (戻るコネクタは上に向かって描かれます)。交差を減らすように順序が整えられ、直角のコネクタは、ブロックの下端から出て、次のブロックの上端に入ります。`LR` と `RL` では、階層が列になります。指定した文字の高さが、すべての大きさの基準になります。

## サブグラフとシーケンス図

- Mermaid の `subgraph name [Title]` … `end` は、そのブロックの周りに、タイトル付きの破線の枠を描きます。サブグラフは入れ子にできます。配置では他のブロックを枠の外に保つことはないため、枠に入ってしまったブロックはグリップで移動してください。
- Mermaid の `sequenceDiagram`、または `participant` 行と `->` メッセージを含む PlantUML のテキストは、上部に並んだブロックとして描かれます。それぞれの下に破線の生存線があり、メッセージごとに1行が描かれます。`-->` と `-->>` は破線、`->>` と `-)` は矢印の先端を持ちます。`autonumber` はメッセージに番号を付け、自分自身へのメッセージはループになります。注記と `loop` / `alt` の枠は読み飛ばされます。

## 単線図と配管図のシンボル

ブロックは、ボックスの代わりに、名前を下に付けた描画シンボルにもできます。テキストでシンボルを指定します:

| テキスト | 指定方法 |
|---|---|
| Mermaid | `P1[Feed pump]:::pump-cf` または `class P1 pump-cf` の行 |
| D2 | `P1.shape: pump-cf` または `P1: Feed pump { shape: pump-cf }` |
| PlantUML | `component P1 <<pump-cf>>` |
| from-to リスト | 列 `from_symbol` と `to_symbol` |

名前は、P&ID のシェイプ (`pump-cf`、`tank`、`gate`、`ball`、`exch-shell`、`inst-field` など、P&ID ライブラリの残り) と、電気のセット (`contact.no`、`breaker`、`motor.3ph`、`transformer`、`lamp` など) です。2つのセットで共通する名前は P&ID のセットに割り当てられます。電気のセットを選ぶ場合は、前に `pid:` または `el:` を付けます。CadCraft が知らない名前は読み飛ばされ、件数が数えられます。シンボルは `Diagram` レイヤーに、単純な線、円、円弧で描かれ、文字の高さに合わせて縮尺されます。タグ付きのアドオンのブロックではないため、実際の作図には P&ID または電気のコマンドを使ってください。

ウィンドウ内の AIアシスタントも、`diagram_from_text` ツールを使って同じことができます。
