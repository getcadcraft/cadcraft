## သင်လုပ်မည့်အရာ

သင်သည် Ana ဖြစ်ပြီး **Riverside Clinic** တွင် Ben ဟူသော အလုပ်ဖော်နှင့်အတူ အလုပ်လုပ်သည်။ ပရောဂျက်၏ ပုံဆွဲများသည် သင်နှစ်ဦးစလုံး ဝင်ရောက်နိုင်သော ဖိုင်တွဲတစ်ခုတွင် နေသည် (မျှဝေ drive၊ ထပ်တူပြုထားသော ဖိုင်တွဲ၊ သို့မဟုတ် cloud ဖိုင်တွဲ)။ အဆုံးတွင် ဖိုင်တစ်ခုသည် ပထမမိတ္တူမှ ထုတ်ဝေထားသော ပြင်ဆင်မှု **A** အထိ ရောက်သွားပြီး၊ **B.1** အဖြစ် ထပ်ပြောင်းထားပြီး၊ ဘယ်သူ ဘာလုပ်သလဲ သင် မြင်ပြီး၊ ဖိုင်ကို သင်ကိုင်ထားစဉ် Ben မြင်သည့်အရာကိုလည်း သင် မြင်ရမည်။

အရာအားလုံးကို ဖိုင်များ ဘေးရှိ ဝှက်ထားသော `.ccvault` ဖိုင်တွဲတွင် သိမ်းသည်: ဆာဗာ မရှိ၊ ဘာမျှ မတင်ပါ (cloud ဖိုင်တွဲသည် ခြွင်းချက် ဖြစ်သည်၊ နောက်ဆုံး အဆင့်ကို ကြည့်ပါ)။ ခလုတ်နှင့် စည်းမျဉ်းအားလုံးကို တစ်နေရာတည်းတွင် ကြည့်ရန် သင့်အက်ပ်တွင် ရှိသော *စာရွက်စာတမ်းများနှင့် ပြင်ဆင်မှုများ* ခေါင်းစဉ်ကို ကြည့်ပါ။

## ၁။ ပရောဂျက် ဖိုင်တွဲ သတ်မှတ်ခြင်း

1. **မြင်ကွင်း** tab ၏ **နောက်ထပ်** မီနူးမှ {{ui:Documents…}} ကို ရွေးပါ၊ သို့မဟုတ် `DOCUMENTS` (သို့မဟုတ် `DOCS`) ကို ရိုက်ပြီး {{key:Enter}} နှိပ်ပါ။
2. {{ui:Choose the project folder}} ကို ရွေးပြီး ပရောဂျက်၏ ပုံဆွဲများ ရှိသော ဖိုင်တွဲကို ရွေးပါ။ (ပရောဂျက် ဖိုင်တွဲများသည် Studio နှင့် ဖိုင်တွဲကို ဖွင့်နိုင်သော browser များ၊ ဥပမာ Chrome နှင့် Edge တွင် အလုပ်လုပ်သည်။ အခြား browser များတွင် panel က ထိုသို့ ပြောသည်။)
3. **သင်:** ဘေးရှိ {{ui:Change}} ကို ရွေးပြီး အမည် `Ana` ကို ရိုက်ပါ (မေးလျှင် ဤကွန်ပျူတာ၏ အမည်လည်း)။ panel က ယခု *သင်: Ana on* နှင့် သင့်ကွန်ပျူတာ ဟု ပြသည်။ သင့်အမည်သည် သင်လုပ်သမျှ အရာတိုင်းတွင် ပါသည်။
4. {{ui:Start a vault in this folder}} ကို ရွေးပြီး ပရောဂျက် အမည် `Riverside clinic` ကို ရိုက်ပါ။ panel က *Riverside clinic အတွက် vault စတင်ပြီး။* ဟု ပြသည်။

## ၂။ ဖိုင်တစ်ခုကို ထိန်းချုပ်ခြင်း

1. **vault တွင် မရှိသော ဖိုင်များ** ကို ဖွင့်ပြီး `plans/A-101.dxf` ဘေးရှိ {{ui:Add}} ကို ရွေးပါ။
2. ၎င်းသည် **vault ထဲရှိ ဖိုင်များ** အောက်တွင် ပြင်ဆင်မှု **A.1** နှင့် အခြေအနေ **လုပ်ဆောင်နေဆဲ** ဖြင့် ပေါ်လာသည်။ A.1 သည် ၎င်း၏ ပထမ မိတ္တူ ဖြစ်သည်; vault သည် ပြင်ဆင်မှု တိုင်း၏ မိတ္တူကို ထိန်းသည်။

## ၃။ Check out၊ ပြောင်းခြင်း၊ Check in

1. `plans/A-101.dxf` ဘေးရှိ {{ui:Open}} ကို ရွေးပါ။ ပုံဆွဲ CadCraft တွင် ဖွင့်ပြီး panel ပိတ်သည်၊ သင်မြင်နိုင်ရန်။ panel သည် command တစ်ခုအကွာ ရှိနေဆဲ: `DOCUMENTS`။
2. panel ကို ပြန်ဖွင့်ပြီး {{ui:Check out}} ကို ရွေးပါ။ အတန်းက ယခု **သင့်ထံ check out လုပ်ထား** ဟု ပြသည်။ `.ccvault/locks` တွင် လော့ခ် ဖိုင် ဖန်တီးထားသည်; သင် check in မလုပ်မချင်း အခြား မည်သူမျှ ဤဖိုင်ကို check out မလုပ်နိုင်ပါ။
3. တစ်ခုခု ဆွဲပါ: မျဉ်းတစ်ကြောင် ထည့်၊ နံရံ ရွှေ့။ ပုံဆွဲကို သင့်ထံ check out မလုပ်ထားလျှင် vault ဖိုင်အပေါ် မည်သည့်အရာမျှ သိမ်းမရပါ; **အမည်ပြောင်း၍ သိမ်းရန်** သည် သင့်ကိုယ်ပိုင် မိတ္တူအတွက် အမြဲ အလုပ်လုပ်သည်။
4. panel ကို ဖွင့်၊ {{ui:Check in}} ကို ရွေးပြီး ပြောင်းလဲမှုကို ရိုက်ပါ (`Moved the door`)။ panel က *A.2 အဖြစ် check in လုပ်ပြီး* ဟု ပြသည်။ ပရောဂျက် ဖိုင်တွဲရှိ ဖိုင်သည် ယခု သင်ဖွင့်ထားသော ပုံဆွဲ ဖြစ်ပြီး လော့ခ် ပျောက်သွားသည်။ ပြောင်းလဲမှု မရှိဘဲ check in လုပ်လျှင် ပြင်ဆင်မှု မပြောင်းပါ။

စိတ်ပြောင်းလျှင် {{ui:Undo check-out}} က ပြင်ဆင်မှုအသစ် မဖန်တီးဘဲ ဖိုင်ကို ပြန်ပေးသည်။

## ၄။ ပြန်လည်သုံးသပ်ခြင်းနှင့် ထုတ်ဝေခြင်း

1. {{ui:Send for review}} ကို ရွေးပါ။ အခြေအနေသည် **သုံးသပ်ရန်** ဖြစ်ပြီး ဖိုင်သည် ဖတ်ရုံသာ ဖြစ်သည်။
2. အတည်ပြုမည်မတိုင်မီ {{ui:Project settings}} ကို ရွေး၍ ဘယ်သူ အတည်ပြုနိုင်သလဲ စာရင်းပြုပါ (တစ်ကြောင်းတစ်အမည်)၊ ဥပမာ `Ben` နှင့် `Carla`၊ ထို့နောက် အတည်ပြုသူသည် ရေးသားသူ မဟုတ်ရမည့် စည်းမျဉ်းကို အမှတ်ခြစ်ပါ။ {{ui:Save settings}} ကို ရွေးပါ။ ယခု vault ကိုယ်တိုင်က အခြားသူကို ငြင်းပယ်သည်။
3. Ben (သို့မဟုတ် Carla) က {{ui:Approve}} ကို ရွေးပြီး အတည်ပြုသူ အမည်ကို ရိုက်ပါ။ အခြေအနေသည် **ထုတ်ဝေပြီး** ဖြစ်ပြီး ပြင်ဆင်မှုသည် **A** ဖြစ်လာသည်၊ *approved by* နှင့် အမည်ဖြင့်။ ထုတ်ဝေထားသော ဖိုင်သည် ဖတ်ရုံသာ ဖြစ်သည်။ {{ui:Send back}} က အကြောင်းပြချက်ဖြင့် လုပ်ဆောင်နေဆဲ သို့ ပြန်ပို့မည်ဖြစ်သည်။

အတည်ပြုသူ၏ အမည်သည် panel တွင် ရိုက်ထားသော အမည်ဖြစ်သည်; ၎င်းသည် ဘယ်သူ လက်မှတ်ထိုးသလဲ မှတ်တမ်း ဖြစ်ပြီး ကိုယ်ရေးအထောက်အထား မဟုတ်ပါ။

## ၅။ ပြင်ဆင်မှု အသစ်

1. ထုတ်ဝေထားသော ဖိုင်တွင် {{ui:New revision}} ကို ရွေးပါ။ နောက်အက္ခရာအတွက် ၎င်းကို ကိုင်ထားသည်။
2. ပြောင်းပြီး {{ui:Check in}} လုပ်ပါ။ ပြင်ဆင်မှုသည် **B.1** ဖြစ်ပြီး လုပ်ဆောင်နေဆဲ။ တူညီနည်းဖြင့် ထုတ်ဝေလျှင် **B** ဖြစ်လာသည်။ ပထမ check in မတိုင်မီ {{ui:Undo check-out}} သည် **A** တွင် ထားသည်။

ပြင်ဆင်မှု အက္ခရာများသည် A၊ B … Z၊ AA၊ AB ဖြင့် ဆက်သွားသည်။ သင့်စံက အက္ခရာအချို့ ချန်ထားလျှင် ပရောဂျက် ဆက်တင် *Use the ASME Y14.35 sequence* က နောက်ပြင်ဆင်မှုများအတွက် I၊ O၊ Q၊ S၊ X နှင့် Z ကို ကျော်သည်။

## ၆။ ဘာဖြစ်ခဲ့သလဲ ကြည့်ခြင်း

ဖိုင်အမည်ကို ရွေး၍ အသေးစိတ် ဖွင့်ပါ:

- **{{ui:History}}**: ဖြစ်ရပ် အားလုံး၊ အသစ်ဆုံးက အရင်၊ ဘယ်သူ၊ ဘယ်ကွန်ပျူတာနှင့် ဘယ်အချိန်ဖြစ်သည်ကို ပါ: Ana က *Checked in A.2*၊ Ben က *Released* နှင့် အခြား။
- **{{ui:Revisions}}**: ပြင်ဆင်မှု ဇယား။ {{ui:Open copy}} က ပြင်ဆင်မှုကို vault ဖိုင်ကို မထပ်ရေးနိုင်သော ရိုးရိုးမိတ္တူအဖြစ် ဖွင့်သည်; {{ui:Compare with}} က ယခင်ပြင်ဆင်မှု သို့မဟုတ် အခြားတစ်ခုနှင့် နှိုင်းယှဉ်၍ ထည့်ထား၊ ဖယ်ထား၊ ပြောင်းထားသည်များကို စာရင်းပြုသည်။
- **{{ui:Uses}}**: ၎င်းချိတ်ဆက်ထားသော ပုံဆွဲများ (xrefs)။
- **{{ui:Used by}}**: Used by သည် ဤအရာကို ချိတ်ဆက်ထားသော vault ရှိ အခြားပုံဆွဲအားလုံးကို ဖော်ပြသည်: အခြေခံ ပလန်ကို ပြောင်းလျှင် ဘယ်စာရွက်များ စစ်ရမလဲ သိသည်။

## စာရွက်ပေါ်ရှိ ပြင်ဆင်မှု

ပုံဆွဲ ဖွင့်ထားစဉ် (နှင့် layout တစ်ခု ရှိစဉ်) {{ui:Revision block}} ကို ရွေးပါ: ထုတ်ဝေထားသော ပြင်ဆင်မှု ဇယားကို စာရွက်၏ ညာဘက်အပေါ်ထောင့်တွင် ဆွဲသည်။ {{ui:Fill title blocks}} ကို ရွေး၍ REV၊ VAULT.REV၊ VAULT.STATE၊ VAULT.DATE သို့မဟုတ် APPROVED_BY ဟု tag လုပ်ထားသော title-block attributes များကို ဖိုင်၏ ပြင်ဆင်မှု၊ အခြေအနေ၊ ရက်စွဲနှင့် အတည်ပြုသူဖြင့် ဖြည့်သည်။ နောက်ထုတ်ဝေမှုကို အတည်ပြုလျှင် revision block ကို ရက်စွဲ ပြန်ညှိသည်။

## ၇။ သင်ဖိုင်ကိုင်ထားစဉ် Ben မြင်ရသည်များ

ယခု ဖိုင်ကို ပြန် check out လုပ်ပြီး Ben ကို သူ့ကွန်ပျူတာတွင် တူညီသော ပရောဂျက် ဖိုင်တွဲကို ဖွင့်ရန်နှင့် panel ဖွင့်ရန် ပြောပါ။ ဖိုင်၏ အတန်းတွင် သူက **Checked out by Ana on** သင့်ကွန်ပျူတာ **ကတည်းက** အချိန်ကို မြင်ပြီး **Check out** ခလုတ် မရှိပါ။ ဘာပဲဖြစ်ဖြစ် ကြိုးစားလျှင် vault က ငြင်းပယ်သည်: လော့ခ်သည် စနစ်က နှစ်ကြိမ် မဖန်တီးမည့် ဖိုင်ဖြစ်သောကြောင့် ဖိုင်တွဲသည် Studio တွင် disk ပေါ်ရှိသောအခါ၊ စက္ကန့်တူသည့်အချိန်တွင်ပင် လူနှစ်ဦး ဖိုင်ကို တစ်ပြိုင်နက် မကိုင်နိုင်ပါ။ (browser တွင် ဖိုင်တွဲက အကောင်းဆုံး ကြိုးစားမှုသာ ခွင့်ပြုပြီး panel က **Folder** အောက်တွင် ထိုသို့ ပြောသည်။)

Ana မရှိပြီး Ben ကို ဖိုင် လိုအပ်လျှင် {{ui:Break check-out}} က လွတ်စေသည်။ အကြောင်းပြချက် ရိုက်ရမည်; ၎င်းသည် ဘယ်သူ၏ check-out ဖြစ်သည်နှင့်အတူ မှတ်တမ်းထဲ ရောက်သည်။ ပရောဂျက်က admin များ ဖော်ပြထားလျှင် သူတို့သာ လုပ်နိုင်သည်။ stale limit (မူလ 14 ရက်) ထက်ဟောင်းသော check-out ကို *a long time* ဟု မှတ်သည်။ ဖြတ်ပြီးနောက် Ana ၏ နောက်ကျသော check-in ကို ငြင်းပယ်သဖြင့် သင်နှစ်ဦး တစ်ဦးကိုတစ်ဦး မထပ်ရေးနိုင်ပါ။

## ၈။ Cloud ဖိုင်တွဲများ

cloud ဖိုင်တွဲသည် သင့်အဖွဲ့၏ cloud သိုလှောင်မှုတွင် ထားသော ပရောဂျက် ဖိုင်တွဲ ဖြစ်သောကြောင့် အဖွဲ့သည် မျှဝေ drive မလိုပါ။ Studio တွင် သင့် CadCraft အကောင့်ဖြင့် ဝင်ထားလျှင် panel က {{ui:Choose the project folder}} ဘေးတွင် {{ui:Open a cloud folder}} ကို ပြသည်။ ထိုကို ရွေးပြီး ဖိုင်တွဲကို ရွေးပါ၊ workspace / folder ဟု စာရင်းပြုထားသည်။ workspace ပိုင်ရှင်က ဖိုင်တွဲကို အရင် ဖန်တီးရမည်၊ အဖွဲ့၏ cloud သိုလှောင်မှု အသုံးဝင်ရမည်။ အထက်ပါ အရာအားလုံး တူညီစွာ အလုပ်လုပ်သည်; ဆာဗာက လော့ခ်ကို ဖန်တီးပြီး လူများကြား တင်းကျပ်သည်။ ဝင်ထားခြင်း မရှိလျှင် panel က ဝင်ရန် ပြောသည်။ ပုံမှန် browser tab တွင် cloud ခလုတ် မပေးပါ; Studio ကို သုံးပါ။

## စမ်းကြည့်ပါ

အထက်ပါ ရှစ်ဆင့်ကို အမှန်ဖိုင်၏ မိတ္တူဖြင့် လုပ်ကြည့်ပါ။ လူနှစ်ဦးအဆင့်များအတွက် အခြားလူ တစ်ဦး၊ သို့မဟုတ် အမည်နှစ်ခုဖြင့် window နှစ်ခု လိုအပ်သည်။ အမှန် မျှဝေ ဖိုင်တွဲဖြင့် စမ်းလျှင် Community testing စာမျက်နှာတွင် ဤအရာကို အတိအကျ မေးသော စစ်ဆေးမှုရှိပြီး ရလဒ်များ လက်ခံသည်။
